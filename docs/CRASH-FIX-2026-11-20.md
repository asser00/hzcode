# Crash fix log - 2026-11-20 - horde_soldiers 2.0.1 on Apocalypssia-4.94

Instance: `E:\Games\Minecraft\instances\Apocalypssia-4.94\minecraft`
(MC 1.20.1, Forge 47.4.28, Sinytra Connector, PolyMC launcher, offline account `xsier`).
Symptom: the game crashed immediately on launch whenever `horde_soldiers-2.0.1.jar` was in `mods\`.

Four independent defects were found and fixed. All broken jars were MOVED (never deleted) into
`DELETED\` folders with READMEs. The working jar is `build\libs\horde_soldiers-2.0.1.jar`
(SRG-reobfuscated, BOM-free, clean manifest) and is installed in the instance's `mods\`.

## Defect 1 - UTF-8 BOM in META-INF\mods.toml (crash at 12:10, 2026-11-19)
- Log: `ModFileLoadingException: Mod candidate horde_soldiers-2.0.1.jar contains a corrupt or
  misconfigured toml` (fatal during mod discovery, `logs\stderr_stream.log`).
- Root cause: the old `build-offline.ps1` wrote the expanded `mods.toml` with
  `Set-Content -Encoding utf8`, which under Windows PowerShell 5.1 prepends a BOM (`EF BB BF`).
  Forge's `ModFileParser` reads mods.toml as UTF-8 WITHOUT stripping the BOM, so night-config
  3.6.4 fails at line 1 col 1 (`Invalid bare key: \uFEFFmodLoader`).
- Fix: write with `[System.IO.File]::WriteAllText(..., [System.Text.UTF8Encoding]::new($false))`
  and assert the first 3 bytes are not `EF BB BF`; `tools\run-tests.ps1` now does a byte-level BOM
  check (text search misses it because `Get-Content` strips the BOM).

## Defect 2 - jar was never reobfuscated mojmap->SRG (crash at 00:43, 2026-11-20)
- Log: `java.lang.NoSuchMethodError: 'EntityType$Builder EntityType$Builder.of(EntityType$EntityFactory,
  MobCategory)'` at `ModEntities.lambda$static$0(ModEntities.java:22)` during the ENTITY_TYPE
  RegisterEvent, cascading into `NullPointerException: Registry Object not present:
  horde_soldiers:zombie` at `ModEntities.lambda$static$4(ModEntities.java:31)` (spawn-egg lambda).
- Root cause: the offline build compiled with `javac` against the MOJMAP forge jar
  (`build\cp\forge-mapped.jar`) and shipped that jar as-is. But the production game runs with
  SRG names (`ModLauncher naming: srg`, runtime `client-1.20.1-20230612.114412-srg.jar`).
  Distributed Forge mods are reobfuscated mojmap->SRG at BUILD time by ForgeGradle; a raw javac
  jar keeps mojmap names and every MC call fails at runtime. Proof: the old working
  `E:\Games\horde_soldiers-1.0.0.jar` calls `EntityType$Builder.m_20704_` (SRG) directly, and
  TACZ's jar references SRG names (`m_10595_`, `m_41728_`, ...). `of` in mojmap == `m_20704_` in SRG.
- Fix: build the production jar with the cached Gradle (`gradle --offline build`, ForgeGradle
  6.0.54 reobfs automatically). Verified in the shipped jar: `EntityType$Builder.m_20704_`
  present, no `Builder.of:` left. NOTE: `gradle jar` alone does NOT reobf - the full `build`
  task is required (the reobf step is wired into it).

## Defect 3 - spawn eggs called RegistryObject.get() inside the register lambda
- `new SpawnEggItem(ZOMBIE.get(), ...)` in the ITEM RegisterEvent lambda. Any failure of the
  ENTITY_TYPE registration (defect 2) turns this into the NPE above.
- Fix: use `net.minecraftforge.common.ForgeSpawnEggItem(RegistryObject, bg, fg, props)` -
  the Supplier-based constructor defers the entity lookup.

## Defect 4 - manifest attribute FMLModType=GAME (crash at 02:05, 2026-11-20)
- Log: `java.lang.IllegalArgumentException: No enum constant
  net.minecraftforge.forgespi.locating.IModFile$Type.GAME` at `ModFile.<init>` during mod
  scanning (before FML starts; exit code 1, no crash report).
- Root cause: `build.gradle`'s jar manifest set `'FMLModType': 'GAME'`, but forgespi 7.0.1
  (Forge 47.4.28) has no `GAME` enum constant in `IModFile.Type`. The old working 1.0.0 jar's
  manifest has no `FMLModType` at all (defaults to MOD).
- Fix: removed `FMLModType`/`ModLoader`/`LoaderVersion` from the jar manifest attributes.

## Defect 5 - gradle processResources placeholder mismatch
- `src\main\resources\META-INF\mods.toml` uses `${loaderVersion}` but `build.gradle`'s
  replaceProperties only defined `loader_version_range` -> `Missing property (loaderVersion)`.
- Fix: added `loaderVersion: loader_version_range` to replaceProperties.

## Build pipeline now (all offline, no network needed)
`powershell -File build-offline.ps1`:
1. compiles main with javac (JDK 17, `--release 17`) against the cached mojmap forge jar ->
   DEV jar `build\libs\horde_soldiers-2.0.1-dev.jar` (mojmap; TESTS ONLY - never install into the
   game, see defect 2);
2. runs `LogicTests` against the dev jar (114/114 pass);
3. runs cached `gradle --offline build` -> PRODUCTION jar `build\libs\horde_soldiers-2.0.1.jar`
   (SRG-reobfuscated);
4. self-verifies the production jar: mods.toml BOM-free, manifest has no FMLModType,
   `m_20704_` present / no `Builder.of:`, >= 51 classes.
`powershell -File tools\run-tests.ps1` smoke-tests the production jar (entries, classes,
spawn-egg models, expanded mods.toml, tacz mandatory dep, BOM, SRG marker, manifest) and runs
LogicTests on the dev jar.
