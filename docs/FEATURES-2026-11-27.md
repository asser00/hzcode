## Male/female character variants (soldiers, scavengers, medics, mercenaries)
- New pure helper `entities/Variant.java`: `Variant.isFemale(uuid, forceFemale)` - deterministic from
  the entity UUID (`SkinVariant.index(uuid, 2) == 1`), so the variant is stable across rejoins and
  world reloads and needs no extra network sync (server and client compute the same value).
  Medics are always female (`forceFemale`).
- `client/ClientModEvents.java`: skin pools are now per gender -
  `assets/hzcode/textures/entity/skins/<type>/male|female/` sub-pools, falling back to the general
  `skins/<type>/` pool when a gender sub-pool is empty. Female entities render with the slim
  (Alex, `ModelLayers.PLAYER_SLIM`) player model, male with the classic `PLAYER` model
  (the renderer swaps the `model` field around `super.render(...)` because
  `LivingEntityRenderer.render` reads the field directly).
- Render type stays `entityCutoutNoCull`; pools resolved via the client `ResourceManager` and cached.

## Mercenary soldiers (the "cannot be tamed but can be traded with" hint)
- New `HordeType.MERCENARY` (faction SOLDIER). Spawn with `/horde spawn mercenary <n>`
  (default group size 3, `mercenary.hordeSize`; natural spawning off by default,
  `mercenary.naturalSpawn`).
- Mercenaries are `SoldierEntity` with a synched+persisted `Mercenary` flag
  (`EntityDataAccessor`, saved in NBT) - no duplicate entity class.
- They get the same TACZ rifle provisioning as soldiers, use the `skins/mercenary/<gender>/` pools,
  and **cannot be tamed**: right-clicking one with the taming treat shows
  "This mercenary cannot be tamed - barter with it instead" (`ModEvents.onEntityInteract`).
  Barter trading and weapon swap keep working for them.
- Wired through `HordeSpawner` (entityTypeFor/defaultSize/initFaction + flag at spawn),
  `HordeController` (same soldier decisions), `ModSpawnPlacements` (spawn-rule config).
